# Context Bundle Generation Prompt Template

> 此模板由 Stage 2 的子 agent 使用。主 agent 按此模板构建子 agent 任务。

## 任务描述

生成 `context-bundle.md`，包含三张映射表。这是连接 AT 树与用例的关键桥梁——后续的语义映射阶段依赖此文件提供的断言目标。

## 输入

- `at-tree-annotated.yaml` — 已标注的 AT-SPI 树（每个交互节点有 comment 字段）
- `ui-map.md`（可选）— 组件图、控件表、菜单索引
- `expected-at-spi-elements.md`（可选）— 预期元素清单
- `docs/modules/*.md`（可选）— 帮助手册章节

## 输出格式

```markdown
## 元素-功能对照表
| 元素名 | Role | 功能描述 | 可见条件 |

## 界面-元素映射
| 界面 | 包含元素 |

## 功能-操作-断言映射
| 功能 | 操作 | 断言目标 |
```

## 三张表的要求

### 1. 元素-功能对照表
- 每行一个交互元素
- 元素名必须与 at-tree-annotated.yaml 中的 name 字段完全一致
- 功能描述从 at-tree-annotated.yaml 的 comment 字段提取
- 覆盖行数 >= AT 树交互节点数的 80%
- 可见条件：元素在什么情况下可见（如"文档打开时"、"设置对话框打开时"）

### 2. 界面-元素映射
- 按 GUI 界面分组（主窗口、工具栏、设置对话框、右键菜单等）
- 每个界面列出其包含的全部元素
- 界面名称与 Stage 3 中 annotation 的"测试界面"字段一致

### 3. 功能-操作-断言映射（最重要）
- 每行描述一个具体的测试功能
- 操作：从用户角度描述到达该功能的操作序列
- 断言目标：操作后应该验证的 AT 元素名（必须来自 at-tree-annotated.yaml）
- 断言目标必须有、且只有一个主要元素。如果操作后多个元素变化，选择最具体的一个

## 示例（格式参考，元素名须来自实际 at-tree-annotated.yaml）

```markdown
## 元素-功能对照表
| 元素名 | Role | 功能描述 | 可见条件 |
|--------|------|----------|----------|
| {打开按钮} | push button | 打开文件触发 | 主窗口工具栏 |
| {设置对话框} | form | 设置窗口 | 主菜单→设置 后出现 |
| {缩放输入框} | text | 缩放比例输入 | 底部工具栏 |
| {滚动条} | scroll bar | 垂直滚动 | 文档区域右侧 |

## 界面-元素映射
| 界面 | 包含元素 |
|------|----------|
| 主窗口-工具栏 | {打开按钮}, {保存按钮}, {打印按钮} |
| 底部栏 | {缩放输入框}, {页码输入框}, {缩放滑块} |
| 设置对话框 | {设置窗口}, {通用标签页}, {显示标签页} |

## 功能-操作-断言映射
| 功能 | 操作 | 断言目标 |
|------|------|----------|
| 打开文件 | 点击打开按钮 → 文件对话框选择文件 | {打开按钮} |
| 缩放至150% | 点击缩放输入框 → 输入150 → 回车 | {缩放输入框} |
| 打开设置对话框 | 主菜单→设置 | {设置对话框} |
| 切换双页显示 | 主菜单→视图→双页 | {文档内容区域} |
| 翻页到下一页 | 按下 PageDown | {文档内容区域} |
```
